# Цепь

Учебный ассистент по варианту 9 «Соединение проводников». Помогает распознавать последовательные и параллельные участки по учебным схемам. Основной урок включает 10 ситуаций. После контрольной доступны ещё две резервные схемы.

## Запуск

Понадобятся Python 3.12 и Node.js 22.12+ (или 24) с pnpm. Проверено на Python 3.12.14 (локально) и 3.10.12 (сервер), Node.js 24.22.3 и pnpm 11.25.0. Команды выполняются из папки `agent`.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте [тренажёр](http://127.0.0.1:8000/) или [схему API](http://127.0.0.1:8000/docs). Для разработки можно запустить `pnpm --dir frontend dev` вместе с FastAPI. На Windows используйте `.venv\Scripts\python.exe` вместо `.venv/bin/python`.

В архиве уже собран каталог `frontend/dist`. Для запуска из архива достаточно установить зависимости Python и запустить FastAPI. Node.js понадобится для повторной сборки после изменения фронтенда.

## GigaChat

Скопируйте `.env.example` в `.env` рядом с этим файлом. При первой настройке внесите значения, затем перезапустите API.

| Переменная | Значение |
| --- | --- |
| `GIGACHAT_CREDENTIALS` | Ключ авторизации проекта из кабинета GigaChat. Префикс Basic не нужен. |
| `GIGACHAT_SCOPE` | По умолчанию `GIGACHAT_API_PERS`. Для другого типа проекта укажите его область доступа. |
| `GIGACHAT_MODEL` | По умолчанию `GigaChat-3-Pro`. |
| `GIGACHAT_CA_BUNDLE` | Путь к дополнительному PEM-сертификату. При пустом значении используется приложенный корневой сертификат. |
| `TUTOR_DB` | Необязательный путь к файлу SQLite. По умолчанию `agent/tutor.sqlite3`. |

Сертификат хранится локально в `certs/` и применяется только в клиенте GigaChat. Источник сертификата указан в [документации Сбера](https://developers.sber.ru/docs/ru/gigachat/certificates). Проект выполняет TLS-проверку. Без ключа сценарий доступен через варианты ответа и подготовленные пояснения.

## Сценарий

Схема и действия текущего шага находятся под последней репликой ассистента. Вариант можно выбрать там же или написать ответ в поле чата.

В начале ассистент объясняет цель урока и сразу показывает схему. Ученик называет резисторы на двух ветвях или сообщает, что затрудняется, а ассистент проверяет расположение элементов. После ответа открывается вопрос об узлах. При ошибке ученик получает подсказку и повторяет попытку. Сообщение о затруднении открывает пояснение. Дальше идут две схемы с пошаговым разбором, четыре с проговариванием, две самостоятельные и две контрольные. При проговаривании нужно назвать действие по памяти, затем записать его результат. Варианты открываются по запросу. Если не видно, куда подключён вывод, вывод о соединении формулируется условно. В контрольной ответ сдаётся выбором одного варианта. Итог оценивает узлы, последовательные и параллельные участки и обоснование вывода. Подсказки и проверку правильности система открывает после сдачи обеих контрольных схем.

Для подсказки напишите `Подсказка` в чат. Команды `Разговорный режим` и `Краткий режим` меняют тон реплик с сохранением текущего шага. Эталон и полный разбор можно открыть кнопками или командами `Покажи ответ` и `Полный разбор`. Уточнить термин можно вопросом `Что такое узел?` или командой `Справка параллельное`. Для разбора конкретной учебной схемы укажите номер, например `Полный разбор C02`. После контрольной доступны команды `Резерв C11` и `Резерв C12`.

- `knowledge_base/lesson.json` — определения, поисковые теги и 12 учебных схем. Формат схемы допускает последовательные блоки `s`, параллельные блоки `p` и элемент со скрытым правым выводом `hidden`.
- `app/knowledge.py` — схема, эталоны, варианты и подсказки из одной структуры соединений.
- `app/tutor.py` — этапы урока, режимы и оценивание.
- `app/model.py` — структурированное извлечение GigaChat, подбор помощи и общий бюджет обращения к модели.
- `app/rag.py` — поиск BM25 по карточкам, отдельный контекст помощи и атомарные факты текущей схемы.
- `app/claims.py` — исходные фрагменты реплики, схема извлекаемых утверждений, проверка полноты и совместимости с топологией.
- `app/answers.py` — распознавание названных действий, элементов и узлов, проверка поддерживаемых формулировок и ограничение положительных подсказок модели.
- `app/accounts.py` — регистрация, вход, хеширование паролей и управление сессиями аккаунтов.
- `app/main.py` — API и сохранение состояния и ответов в SQLite.
- `frontend/` — React и MUI X Chat с адаптером FastAPI.

Извлечение решения и помощь по вопросу разделены. Для извлечения GigaChat получает исходную реплику, имена элементов и узлов, текущую задачу и пронумерованные фрагменты исходного текста. Эталон и соединения схемы на этом шаге не передаются. Нативный `response_format` ограничивает JSON-схему ответа. Формат API описан в [документации Сбера](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output).

Сервер проверяет извлечённые пары узлов, группы последовательных и параллельных участков, явное обоснование и общие утверждения по вычисленной топологии. Нельзя добавить отсутствующие узлы или основание из базы знаний. Каждый учитываемый факт связан с фрагментом реплики. Непокрытая физическая часть или неразрешённая неоднозначность требуют уточнения. Перестановка двух выводов неполярного элемента не меняет ответ. Дополнительный вопрос не отменяет проверяемое решение. Смысловая проверка модели остаётся диагностикой и не может превратить неполный или противоречивый набор фактов в правильный.

Для помощи BM25 выбирает до трёх карточек с фильтрацией служебных слов. Отдельный план определяет тему вопроса, работу с понятием или рисунком и необходимость наводки. Определения не получают полный эталон или таблицу соединений; наводки не получают готовое решение. Физический текст ответа составляется дословно из выбранных карточек и вычисленных атомарных фактов. Истинность источника не доказывает, что модель выбрала его уместно: текст пояснений проверяется отдельно от переходов. Внутри одной реплики допускается одна попытка исправить подбор пояснения. Общая граница 35 секунд включает ожидание очереди модели.

В `grounding.source_ids` указаны реально выбранные источники пояснения, в `retrieved_source_ids` — исходный пул поиска. `assessment` показывает результат проверки извлечённых утверждений, `answer_verified` — принят ли такой результат. Баллы и переходы определяет код. Чистый вопрос сохраняет этап, счёт и полный ожидающий подтверждения кандидат. Явный отзыв отменяет прежний кандидат; простое подтверждение без него не даёт балл. При отказе провайдера об этом сообщается прямо, ответ не засчитывается как ошибочный. Контрольная использует явный выбор и не обращается за генеративной подсказкой до сдачи.

Граница проверки — верно извлечённые утверждения поддержанного языка. JSON Schema гарантирует форму, а не полноту понимания произвольной речи. Неизвестные ссылки и неполные формулировки могут потребовать уточнения. Для сложных условных выводов о скрытой связи доступны полные подготовленные варианты. При отсутствии ключа работают закрытые локальные правила, варианты ответа и подготовленные материалы.

## Вход и сохранение урока

Тренажёр открывается в гостевом режиме. Кнопка «Войти» позволяет зарегистрироваться с логином и паролем. Если у аккаунта ещё нет урока, при входе к нему привязывается текущий гостевой урок. При повторном входе, в том числе с другого устройства, открывается последний урок аккаунта.

FastAPI проверяет владельца при чтении и отправке ответа. В SQLite хранятся хеши паролей и токенов аккаунтов. Браузер получает токен в HttpOnly-cookie с ограниченным сроком действия и флагом Secure при HTTPS. Ссылки на гостевые уроки содержат случайный идентификатор, который даёт доступ к гостевой истории, поэтому их следует хранить в пределах своего устройства. Для уже созданной базы SQLite служебные таблицы добавляются при запуске. Если старый урок остался на первой попытке после однозначно правильного ответа о ветвях, при чтении он восстанавливается на составлении способа с сохранением истории. Этапы method и method_compare сохраняются при перезагрузке; прежний compare переводится к предложению способа.

## Проверка

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Протокол и снимки экрана находятся в каталоге `tests` (в архиве — рядом с `agent`). Все 69 unit-тестов используют временный SQLite и обходятся без ключа. После ответа о ветвях предложите план разбора, сопоставьте его с образцом и укажите, что уточните, либо напишите «Использовать образец». Затем начинаются все пять операций C01. Вопросы по теме и перезагрузка сохраняют этап составления/сопоставления способа. Для проверки GigaChat ответьте на вопросы об элементах и узлах первой схемы. На вопрос о последовательных участках напишите «R1 и R2 включены последовательно. Нет ответвлений в узлах C.». Полное проверенное решение получает явное подтверждение и открывает следующий шаг. Сервис также доступен на [fizika.storozhq.ru](https://fizika.storozhq.ru/).

Для воспроизводимой проверки реальной модели выполните из `agent` команду `.venv/bin/python tests/evaluate_dialogue.py --output tests/dialogue_live_results_final.json`. Набор сценариев находится в `tests/dialogue_cases.json`, фактические ответы — в отчёте рядом. Проверка требует настроенного ключа и расходует токены.

Дополнительный набор `tests/followup_cases.json` содержит исходные 10 реплик и 21 новую проверку аудитора. Запуск через FastAPI в отдельной временной SQLite:

```sh
.venv/bin/python tests/evaluate_followups.py --pause 3 --output tests/followup_results.json
```

Этот запуск использует реальный ключ и расходует токены. Он сохраняет полный pending, исходные ответы модели, хеши кода и базы знаний и POST→GET. Блокировка запрещает одновременный запуск двух таких прогонов. Ограничение провайдера останавливает проверку и не считается успехом. Автоматический результат проверяет состояние; правильность, уместность и объём помощи требуют отдельного просмотра. Старые отчёты `dialogue_live_results_final.json` относятся к предыдущей версии; новый аудит не заменяется их успешными метриками.

Независимый offline-набор API можно повторить командой `.venv/bin/python tests/audit_evidence/api_regressions.py --output /tmp/circuit-api-results.json`. Он проверяет 12 сценариев, включая сохранение pending и откат конкурентного хода, не читает секреты и не обращается к провайдеру. Итоги улучшений и границы проверки приведены в `tests/protocol.md`.
