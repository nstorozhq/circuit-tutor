# Цепь

Учебный ассистент по варианту 9 «Соединение проводников». Помогает распознавать последовательные и параллельные участки по учебным схемам. Основной урок включает 10 ситуаций. После контрольной доступны ещё две резервные схемы.

## Запуск

Понадобятся Python 3.12 и Node.js 22.12+ (или 24) с pnpm. Проверено на Python 3.12.14, Node.js 24.22.3 и pnpm 11.25.0. Команды выполняются из папки `agent`.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте [тренажёр](http://127.0.0.1:8000/) или [схему API](http://127.0.0.1:8000/docs). Для разработки можно запустить `pnpm --dir frontend dev` вместе с FastAPI. На Windows используйте `.venv\Scripts\python.exe` вместо `.venv/bin/python`.

В архиве уже собран каталог `frontend/dist`. Для запуска из архива достаточно установить зависимости Python и запустить FastAPI. Node.js понадобится для повторной сборки после изменения фронтенда.

## GigaChat

Скопируйте `.env.example` в `.env` рядом с этим файлом. При первой настройке внесите значения, затем перезапустите API.

| Переменная | Значение |
| --- | --- |
| `GIGACHAT_CREDENTIALS` | Ключ авторизации проекта из кабинета GigaChat. Префикс Basic не нужен. |
| `GIGACHAT_SCOPE` | По умолчанию `GIGACHAT_API_PERS`. Для другого типа проекта укажите его область доступа. |
| `GIGACHAT_MODEL` | По умолчанию `GigaChat-3-Pro`. |
| `GIGACHAT_CA_BUNDLE` | Путь к дополнительному PEM-сертификату. При пустом значении используется приложенный корневой сертификат. |
| `TUTOR_DB` | Необязательный путь к файлу SQLite. По умолчанию `agent/tutor.sqlite3`. |

Сертификат хранится локально в `certs/` и применяется только в клиенте GigaChat. Источник сертификата указан в [документации Сбера](https://developers.sber.ru/docs/ru/gigachat/certificates). Проект выполняет TLS-проверку. Без ключа сценарий доступен через варианты ответа и подготовленные пояснения.

## Сценарий

Схема и действия текущего шага находятся под последней репликой ассистента. Вариант можно выбрать там же или написать ответ в поле чата.

В начале ассистент объясняет цель урока и сразу показывает схему. Ученик называет резисторы на двух ветвях или сообщает, что затрудняется, а ассистент проверяет расположение элементов. После ответа открывается вопрос об узлах. При ошибке ученик получает подсказку и повторяет попытку. Сообщение о затруднении открывает пояснение. Дальше идут две схемы с пошаговым разбором, четыре с проговариванием, две самостоятельные и две контрольные. При проговаривании нужно назвать действие по памяти, затем записать его результат. Варианты открываются по запросу. Если не видно, куда подключён вывод, вывод о соединении формулируется условно. В контрольной ответ сдаётся выбором одного варианта. Итог оценивает узлы, последовательные и параллельные участки и обоснование вывода. Подсказки и проверку правильности система открывает после сдачи обеих контрольных схем.

Для подсказки напишите `Подсказка` в чат. Команды `Разговорный режим` и `Краткий режим` меняют тон реплик с сохранением текущего шага. Эталон и полный разбор можно открыть кнопками или командами `Покажи ответ` и `Полный разбор`. Уточнить термин можно вопросом `Что такое узел?` или командой `Справка параллельное`. Для разбора конкретной учебной схемы укажите номер, например `Полный разбор C02`. После контрольной доступны команды `Резерв C11` и `Резерв C12`.

- `knowledge_base/lesson.json` — определения, поисковые теги и 12 учебных схем. Формат схемы допускает последовательные блоки `s`, параллельные блоки `p` и элемент со скрытым правым выводом `hidden`.
- `app/knowledge.py` — схема, эталоны, варианты и подсказки из одной структуры соединений.
- `app/tutor.py` — этапы урока, режимы и оценивание.
- `app/model.py` — запросы к GigaChat с найденными источниками, разбор JSON и проверка цитат.
- `app/rag.py` — поиск BM25 по карточкам и подбор контекста текущей схемы. Схема результата ограничивает намерение, вариант ответа, утверждения о ветвях и цитаты.
- `app/answers.py` — распознавание названных действий, элементов и узлов, проверка поддерживаемых формулировок и ограничение положительных подсказок модели.
- `app/accounts.py` — регистрация, вход, хеширование паролей и управление сессиями аккаунтов.
- `app/main.py` — API и сохранение состояния и ответов в SQLite.
- `frontend/` — React и MUI X Chat с адаптером FastAPI.

Свободная учебная реплика сначала проходит RAG. BM25 ранжирует карточки из `lesson.json` по тексту реплики и текущему вопросу, выбирает до трёх карточек. Сервер добавляет подсказку текущего шага и его эталон либо описание текущего рисунка. Другие схемы в запрос не попадают. Для просьбы о подсказке эталон исключается из контекста.

Диалог обрабатывается отдельными шагами. GigaChat сначала определяет намерение по текущему вопросу и последним шести репликам. Для содержательного ответа затем извлекает утверждения о ветвях или выбирает вариант. Перед предложением правильного варианта выполняется дополнительная проверка смыслового соответствия. Для вопроса, затруднения, уточнения и неполного ответа модель формулирует короткое пояснение по найденным источникам. Пояснение проходит отдельную проверку фактов по найденным источникам. Если она выявляет противоречие, используется дословный материал выбранного источника. Сервер также проверяет идентификаторы источников и обозначения элементов. Вопросы и просьбы о помощи сохраняют текущий шаг и ожидающее подтверждения решение. Утверждения обо всех элементах дополнительно сверяются с топологией, а порядковые ссылки на элементы разрешаются по текущему набору обозначений. Для полностью проверяемых утверждений результат сверки по схеме имеет приоритет над категорией, предложенной моделью. Приветствие в той же реплике не отменяет проверки ответа. Определения понятий ищутся по тексту вопроса с повышенным весом и без добавления описания рисунка, когда вопрос относится к термину. Для ветвей сверяются все названные элементы, их наличие в исходной реплике ученика и расположение на схеме. В других заданиях семантическое сопоставление выполняет модель, а сервер проверяет структуру, допустимость варианта и сохраняет исходный ответ как основание предложения, затем запрашивает подтверждение ученика. Ошибки смыслового сопоставления модели остаются возможными.

В истории API у сообщения есть `grounding.status` и `grounding.source_ids`. По ним можно проверить реальный вызов RAG и состав контекста. Числовые баллы и переходы определяет сценарий. Контрольная использует явный выбор, до её сдачи справка и эталоны закрыты. Вопрос, сомнение, неполный ответ и уточнение обрабатываются общей политикой на всех тренировочных этапах. Они сохраняют шаг и оценку. На этапе проговаривания помощь ограничена текущим действием алгоритма, а контрольная закрыта для генеративных подсказок. Если решение уже ожидало подтверждения, вопрос его не сбрасывает. При неполном обосновании сформулированного решения ассистент предлагает уточнить смысл без немедленной оценки. Это пояснение доступно и при сбое модели. При недоступной модели ответ, требующий оценивания, сохраняет шаг, а ученик получает предложение повторить запрос. Без настроенного ключа доступны локальные правила и варианты.

## Вход и сохранение урока

Тренажёр открывается в гостевом режиме. Кнопка «Войти» позволяет зарегистрироваться с логином и паролем. Если у аккаунта ещё нет урока, при входе к нему привязывается текущий гостевой урок. При повторном входе, в том числе с другого устройства, открывается последний урок аккаунта.

FastAPI проверяет владельца при чтении и отправке ответа. В SQLite хранятся хеши паролей и токенов аккаунтов. Браузер получает токен в HttpOnly-cookie с ограниченным сроком действия и флагом Secure при HTTPS. Ссылки на гостевые уроки содержат случайный идентификатор, который даёт доступ к гостевой истории, поэтому их следует хранить в пределах своего устройства. Для уже созданной базы SQLite служебные таблицы добавляются при запуске. Если старый урок остался на первой попытке после однозначно правильного ответа о ветвях, при чтении он восстанавливается на вопросе об узлах с сохранением истории.

## Проверка

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Протокол и снимки экрана находятся в каталоге `tests` (в архиве — рядом с `agent`). Проверка использует временный SQLite и обходится без ключа. Для проверки GigaChat ответьте на вопросы о ветвях и узлах первой схемы. На вопрос о последовательных участках напишите «R1 и R2 включены последовательно. Нет ответвлений в узлах C.». Ассистент предложит подтвердить интерпретацию. Сервис также доступен на [fizika.storozhq.ru](https://fizika.storozhq.ru/).

Для воспроизводимой проверки реальной модели выполните из `agent` команду `.venv/bin/python tests/evaluate_dialogue.py --output tests/dialogue_live_results_final.json`. Набор сценариев находится в `tests/dialogue_cases.json`, фактические ответы — в отчёте рядом. Проверка требует настроенного ключа и расходует токены.
